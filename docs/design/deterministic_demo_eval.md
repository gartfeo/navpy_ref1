# Deterministic 3-UAV GCS demo eval

## Goal
Given the same manifest and seed, `scripts/eval_gcs_navigation_demo.py` (SITL x3 + NavPy x3 + GCS backend) produces a bit-identical tick journal, event sequence, assignments, commands, logs and metrics. This holds per host, per `firmware.lock` and per `.venv` lock. Stock SITL paced against the wall at 10x cannot do this. The fix is an opt-in, eval-only lockstep mode. Wall mode stays the default and keeps working.

## Design
| Part | Mechanism |
|---|---|
| Clock | A Fleet Coordinator in the eval process (Windows `.venv`) owns tick k. t_k is the integer `source_us` the SITLs report for tick k (`AP_HAL::micros64`, `NavPyGuidanceStep.cpp:157,166`), never `truth_us` (`:310`). All SITLs must agree, or it is a config fault. `RuntimeTime` gives `monotonic_us` = t_k and `unix_us` = manifest epoch (= `--start-time`) + t_k. Sleeps round up to whole ticks in integers (reuse `determinism_slots.py`). Nothing else advances time. Wall time is only a supervision budget: a breach is a host fault, never a different outcome. |
| SITL x3 (eval-only build) | A new `serial-step` mode, next to the existing closed-loop mode. The FAST_TASK `sim_guidance_step` (`ArduPlane.cpp:58-60`) freezes the clock as it does today (`NavPyGuidanceStep.cpp:153-184`). It sends the existing header plus the bytes drained from serial0 and serial1, on a new `step` devtype (devtype chain at `UARTDriver.cpp:115-176`).<br>Inbound bytes go to a per-port FIFO, and each io tick moves at most `readbuffer.space()` into the readbuffer, as the socket path does (`UARTDriver.cpp:950`). FIFO lengths go in the header. Bytes sent at tick k are parsed from k+1 by stock MAVLink code.<br>The header also counts clock advances not caused by the loop's own wait (`Semaphores.cpp:41-63`); nonzero is a host fault.<br>Refused in this mode: FTP requests, `SIM_SPEEDUP` != 1, socket devtypes.<br>Other settings: boot id seeded, deadline from env, attitude fence off (`GCS_Mavlink.cpp:1315-1318`), an eval-only env-seeded wall jitter in the non-main branch of `wait_clock` (`SITL_State.cpp:176`) for acceptance (c), EVAL-ONLY banner, sha pinned in `firmware.lock`.<br>The window starts at the first loop, has no cap, and streams its rows. The mode is inert when its env is unset (`:88-89`). |
| WSL side | A repo-owned launcher replaces `run_swarm.sh pi` (`swarm_run_wsl.py:236-238`): no router, serial2 none, `--start-time`, `setarch -R`. A stdlib relay copies AF_UNIX SEQPACKET (`NavPyGuidanceStep.cpp:123-127`) to length-prefixed TCP on a slot-derived port (a new `instance_ports` helper), one connection per SITL. |
| Sysids | Lockstep takes sysids from the manifest (1-3). There is no shared bus or LAN, so slot-derived uniqueness is not needed, and journals are comparable across slots. Wall mode keeps slot sysids. |
| Tick order | 1) Barrier: wait for every SITL frame for tick k.<br>2) Route losslessly with mavlink-router's target and broadcast rules: serial0 to NavPy i; serial1 to the backend and to the other SITLs' serial1 at k+1. Order is fixed: SITL1-3, then backend, then byte order. NAVLINK keeps its product path (companion, AP, radio, AP, companion).<br>3) Send `TICK(k, t_k, bytes, api_requests)` to every participant.<br>4) Collect `DONE` in fixed participant order (outbound frames in send order, API responses, events, membership changes).<br>5) Reply to the SITLs and add the tick's sha256 to the hash chain, over each destination's stream exactly as delivered. |
| Python participants | A `RuntimeTime` port covers clocks, sleep and wait, timers, locks, conditions, queues, threads, the asyncio default executor, RNG, ids and transport. It binds at existing seams: `NavClock` (`nav_clock.py:17-24`), the worker ports (`navigation_command_worker.py:89-90`), cadence (`scheduler_cadence.py:75`), `_dispatch` (`mav_bus_reader.py:74-77`) and `CompanionSwarmState.monotonic_s` (`companion_swarm_state.py:41`).<br>`WallRuntime` is today's behavior.<br>`LockstepRuntime`:<br>- runs the existing threads under a baton: one runs at a time, and waiters wake in (due, creation seq) order;<br>- binds `IdentitySchedulerCadence` (`detector_ports.py:196`);<br>- uses a per-process `Random(seed, ordinal)` and a seeded id factory;<br>- decodes MAVLink without `mavutil.mavfile`.<br>Each TICK: set t_k, dispatch inbound frames in byte order, run to quiescence, check that `threading.enumerate()` equals the managed set, then flush. `END(k_end)` flushes the log worker and the pose-cadence buffers and acks before any process is stopped. Readiness is a registration message, not stdout. |
| GCS backend | The same FastAPI app, in its own process, on an event loop whose `time()`, idle wait, default executor and thread-safe wakeups come from the runtime. It opens no listener. API requests arrive in `TICK` payloads and run through an in-process ASGI transport; each response returns in the `DONE` of the tick in which its handler finishes. WS broadcasts go to a per-tick event journal. The ESP32 trigger is an in-process port that succeeds within the tick; there is no HTTP server. |
| Operator | The existing stack_ops, mission and confirmation code runs on a managed thread under the coordinator's own runtime, through `eval_gcs_demo_ports.py:12-62`. `StackContext` carries the clock, which replaces every `SystemClock()` (`eval_gcs_demo_execution.py:98`, `eval_gcs_demo_confirmation.py:132`, `eval_gcs_demo_mission.py:93`). `JsonApiPort` enqueues requests and parks until their response arrives, while the coordinator keeps ticking. `EventStreamPort` is the journal. The operator reads state only between ticks; NAV start and SNAP come from journal events. Approval happens at the request tick + 15 s of sim time. Command bounds come from named param reads, not MAVFTP. |
| Boot | Only SITLs tick until each acknowledges init (params registered, `AAS_NAV_CGT` present, helpers parked). No fixed boot time replaces that state (the 40 s `simtime_step_artifacts.py:57` window goes). Bytes before the ack are hashed. Participants join only at tick boundaries, in ordinal order, and a spawn holds the clock until it registers. |
| Pure vision | Participants receive t_k (the autopilot clock) and the bytes their product link carries, nothing else. The NVGUID03 truth fields and `truth_us` are not sent, and a schema test pins the `TICK` fields. The final-approach input set is unchanged: the identity cadence changes only timing, never inputs. `ideal_360` stays forbidden. |
| Wall mode | Stays the default. `--lockstep` is opt-in on `eval_gcs_navigation_demo.py` and `gcs_launch.py`. |

### Open contracts (step 6 specifies and prototypes these before any lockstep build)
- **Scheduling:** runnable vs parked states; lock handoff; timeout-vs-input precedence at one tick; one quiescence rule over threads and asyncio together; unique creation seq per worker. `DONE` may leave work parked on future input (a mission upload spans ticks: `mission_upload.py:63`, `message_store.py:119`, `position_service.py:126`). The thread audit checks membership only, not order.
- **UART:** separate enqueue, UART admission, parse and command-apply ticks; egress buffering, short writes and `txspace()`; explicit per-port lengths, acks and overflow errors in a versioned protocol (today's wire: `simtime_navigation_protocol.py:10`). Tests: oversized bursts, a message split across ticks.
- **Router:** pin the mavlink-router version being emulated; specify endpoint learning, unknown targets, component ids, duplicate suppression and AP serial-to-serial forwarding echoes; keep original packet bytes and decoder state across tick fragments. Tests: targeted, broadcast, unknown endpoint, image transfer, repeated AP forwarding.
- **Bus adapter:** one narrow deterministic bus for NavPy and GCS: mode mapping, source identity, MAVLink version and seq, heartbeat admission, close.
- **ASGI:** lifespan run explicitly; request tasks, callbacks and cancellation on the runtime; AnyIO and asyncio pools under the baton; no blocking MAVLink call on the loop thread.
- **Firmware helpers:** HAL token or proof of inertness for scripting, logger and FTP threads; the out-of-loop-advance counter cannot see a helper that mutates state without advancing time.
- **Ownership:** every lockstep process and WSL root is recorded and stopped by ownership, never by sysid pattern; the eval-band launcher rule in `src/gcs/AGENTS.md:60-63` changes in the same PR.
- **Execution model:** compare the general baton with focused synchronous execution at existing worker and service seams; pick the cheaper one that meets the same bar.

## Acceptance
- **Setup:** for a fixture (the 1-UAV fixture at step 9, the certified 3-UAV scenario at step 10), run `eval_gcs_navigation_demo.py --lockstep --seed 1 --run-dir <dir>` twice, with the same manifest, `firmware.lock` and `.venv` lock. Both runs must end at the same terminal tick with zero host faults and zero out-of-loop clock advances.
- **(0) Mission success:** setup passes; the expected assignments, audited approvals and SNAP events occur; the named sim-time scoring gates pass. Two identical failed runs are evidence, not a pass.
- **(a) Journal:** the final sha256 of the per-tick chain must be equal. The chain covers the SITL headers (including FIFO lengths), every serial0 and serial1 byte in both directions, every TICK and DONE payload (including API requests and responses), operator actions and membership changes. Each stream is hashed in delivery order, not as a canonical set. On failure, report the first differing (tick, participant, port, offset).
- **(b) Byte-equal artifacts:**
  - The run-dir inventory must match: the same file-name set, with no pids or wall times in names.
  - The contents must be equal as raw bytes, with no canonicalizer. This covers `report.json`, `operator_approvals.json`, `demo_mission_plan.json`, the companion assignment ledgers, the per-UAV navigation compact, debug and pose-cadence CSVs, the backend event journal and diagnostics timeline, the sim-stamped backend and NavPy logs, and the firmware step CSVs.
  - Excluded by glob only: BIN and `*_host`. run_id and the launch token derive from the seed.
- **(c) Robustness:**
  - The digest stays equal under `HOST_DELAYS_S` (`simtime_navigation_protocol.py:19`) injected into the relay, the coordinator and the participants.
  - It also stays equal under the firmware helper-thread jitter and under CPU load.
  - With manifest sysids, raw journals are equal across slots.
- **Negative controls:**
  - A different seed or one changed waypoint changes the digest.
  - An injected unseeded `random()` is caught by the lint, or by the journal at the first tick where it reaches a byte.
  - An unmanaged `threading.Thread` is caught by the per-tick thread audit.
  - `SIM_SPEEDUP=10` is refused in serial-step.
- **Wall mode:** the existing gates pass, and `python -m pytest tests` is green.

## Not in scope
- Bit identity across machines or library versions. Determinism in wall mode, which gets hermetic inputs only.
- Correctness gaps that become deterministic but stay wrong. These go to `architecture_todo.md`:
  - position and attitude from different ticks, and unstamped airspeed (`sim_source_composition.py:111-117`)
  - float32 auction ties (`linear_assignment.py:24`)
  - single-shot AUTO/ARM sends (`control_launch_actions.py:128-136`)
  - serial1 drops in wall mode (`UARTDriver.cpp:950`)
- Product firmware, which stays stock. `chute_deploy.lua` and `tune_pitch_roll.lua` in lockstep. The uvicorn, WS and ESP32 HTTP transports, which wall mode covers.

## Risks
- **Size:** steps 8-10 touch about 200 NavPy and about 85 backend clock and wait sites, plus 44 backend thread-pool sites. Mitigation: package-sized PRs, the lint test, the thread audit, and a wall eval after each PR.
- **Baton deadlock:** a thread that waits while holding a plain lock blocks everyone. Mitigation: runtime locks, the lint test, and a wall watchdog that dumps every stack and fails the run as a host fault.
- **Firmware helper control:** HAL-token work for scripting, logger and FTP threads may be M-L. Step 6 sizes it; the out-of-loop-advance counter and jitter check only detect part of it.
- **Third-party threads and clocks** (AnyIO workers, library timers) can escape the lint. Mitigation: AnyIO under the baton, the per-tick `threading.enumerate()` audit, and the bus adapter instead of `mavutil.mavfile`.
- **Throughput not measured:** the estimate is 2.5-6x real time, against 10x today, and a 1280x720 confirmation composite per frame may dominate. Step 7 measures it.
- **Lockstep is a different experiment:**
  - Timeouts become sim seconds: GUIDED accept 5 s (`nav_constants.py:18`), CWT 30 s, dwell 45 s.
  - Bytes become eligible at k+1 and parse and apply per the UART contract, cadences round to ticks, and compute (render, law) takes zero sim time.
  - So score changes against wall mode are not regressions. Host latency stays tested in wall mode.
- **Firmware base drift:** `bf0dd8f` has the pitot EAS fix and the demo's `4c23c0a1` does not.
- **Environment:** the WSL-to-Windows TCP link may need a firewall rule.
